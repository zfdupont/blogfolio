# Portfolio

Personal portfolio and blog for [zfdupont.com](http://zfdupont.com). Next.js (App Router) front end, self-hosted behind nginx. An interactive WNBA player-ranking page is backed by a separate Python/Flask stats service.

## Local Development

Package manager is **pnpm**.

```bash
pnpm install
pnpm dev        # http://localhost:3000
```

Other scripts: `pnpm build` (production build), `pnpm start` (serve the build).

To work on the WNBA feature you also need the stats service, which lives in the `projects/wnba-stats` git submodule:

```bash
git submodule update --init        # populate projects/wnba-stats
cd projects/wnba-stats/server
flask --app app run --port 5000    # serves /api/players
```

Note: `server/app.py` reads `../wnbabpm.csv`, so it **must be started from the `server/` directory** or the CSV path will not resolve.

## Deployment

The site is **self-hosted on a DigitalOcean droplet** (Ubuntu). **nginx** sits out front as the reverse proxy / TLS terminator. The Next.js front end (`portfolio`) deploys as a Docker container via GitHub Actions; sibling apps on the same droplet remain on PM2.

### Topology

```
                        ┌──────────────────────────────────────────────┐
  zfdupont.com  ─────▶  │  nginx (:80 / :443)                           │
                        │    /      → Docker   127.0.0.1:3000 (Next.js) │
                        │    /api/  → PM2      127.0.0.1:5000 (Flask)   │
                        └──────────────────────────────────────────────┘
```

- `/` and all site routes: served by the Docker `portfolio` container, bound to `127.0.0.1:3000`.
- `/api/*`: served by the Flask WNBA stats service on PM2 (`flask run`, `127.0.0.1:5000`).
- `huskies.zfdupont.com`: separate project, PM2-managed, unaffected.

**nginx requires no changes.** The existing `nextjs` nginx block already proxies `location /` to `http://127.0.0.1:3000`, which is exactly where the container binds. The `/api` route and the huskies block are unaffected.

### 1. CI/CD deploy (portfolio site)

Push to the `release` branch triggers the GitHub Actions `release` workflow:

1. Builds the Docker image from the repo root `Dockerfile`.
2. Pushes to `ghcr.io/zfdupont/blogfolio` (tagged `:release` and `:<sha>`). The package is public; no registry credentials are needed to pull.
3. SSHes to the droplet and runs:

```bash
cd /root/blogfolio
docker compose pull portfolio
docker compose up -d portfolio
```

The compose service name is `portfolio`; the container binds `127.0.0.1:3000:3000`.

### 2. Rollback

On the droplet, pull any previous image by its Git SHA and retag it as `:release` before restarting the service. No `docker login` is required because the package is public.

```bash
cd /root/blogfolio
IMG=ghcr.io/zfdupont/blogfolio:<previous-sha>
docker pull "$IMG"
docker tag "$IMG" ghcr.io/zfdupont/blogfolio:release
docker compose up -d portfolio
```

### 3. Deploy the WNBA API (PM2, unchanged)

The API is the `projects/wnba-stats` git submodule (`git submodule update --init` if not populated). It runs as `flask run`, which must be started from the `server/` directory because `server/app.py` reads `../wnbabpm.csv`. To update:

```bash
git submodule update --remote     # if the stats service changed
# reinstall deps only if requirements changed:
pip install -r projects/wnba-stats/requirements.txt
pm2 restart 'FLASK_APP=app'       # or by id: pm2 restart 4
```

The rankings CSV is regenerated by the BPM pipeline in the submodule (`scrape.py` → `bpm.py` → `wnbabpm.csv`); see that repo for details. Restart the Flask app after regenerating so it re-reads the CSV.

### 4. One-time droplet cutover

These steps are required once to migrate the droplet from the old PM2 flow to Docker:

1. Install Docker and the compose plugin on the droplet.
2. Check out this repo at `/root/blogfolio` on the `release` branch.
3. Generate an SSH deploy keypair; add the public key to the droplet's `authorized_keys`.
4. Add three GitHub Actions secrets: `DROPLET_HOST`, `DROPLET_USER`, `DROPLET_SSH_KEY`.
5. Stop the old PM2 portfolio process to free port 3000:

```bash
pm2 delete portfolio
pm2 save
```

6. Trigger the Actions workflow (push to `release` or re-run it manually); verify the container starts.
7. After the first push, make the `ghcr.io/zfdupont/blogfolio` package public in the GitHub package settings.

### 5. Local Docker test

```bash
docker build -t blogfolio .
docker run --rm -p 3000:3000 blogfolio
curl localhost:3000
```

### Notes

- Use `pm2 save` after adding or renaming a PM2 process so it is restored on droplet reboot (via `pm2 startup`). This still applies to the Flask API and sibling apps.
- The canonical origin is defined once in `app/sitemap.ts` (`baseUrl`). Update it there if the domain changes.
- `next` is pinned to `canary` and Tailwind is v4 alpha; pin/lock changes can affect the build.
- `@vercel/analytics` and `@vercel/speed-insights` are included but only report telemetry when hosted on Vercel; they are harmless no-ops on this self-hosted deployment.
- The Flask API runs on the built-in dev server (`flask run`). It works, but for a hardening pass consider switching it to gunicorn behind PM2.
